# 仕様: カウンター

`spec_counter.rs` と 1:1 で対応する仕様書。**この md が契約の正本**で、テストはその実行可能な形。
テストを変えるときは先にここを変える（md が動かずテストだけ動く diff は事故の兆候 ── `docs/testing.md`）。

## 用語

`.proto` に現れる語は **`crates/schema/proto/counter.proto` が正典**（用語集を二重に持たない）。
ここで補うのは proto に現れない語だけ。

| 用語             | 定義                                                                                                                                    |
| ---------------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| **カウント値**   | `counter` テーブルの唯一の行（`id = 1`）が持つ `value`。アプリ全体で 1 個しか存在しない                                                 |
| **view-data**    | 「その応答が実際に使ったデータ」を HTML コメント `<!-- view-data ... -->` として埋め込んだデバッグ用の覗き窓。DOM/JS の一部にはならない |
| **フラグメント** | HTMX が要素の中身だけ差し替えるために返す HTML 断片。`<!doctype>` と `<html>` を含まない                                                |

## 前提条件

- アプリが起動済みで `BASE_URL`（既定 `http://127.0.0.1:3000`）で応答する。
- migrations 適用済みで `counter` に `id = 1` の行がある（`./run db-setup`）。
- **カウント値の絶対値は前提にできない。** テストは並列に走り、開発サーバのブラウザ操作でも
  同じ行が動く。値を動かす経路は増加のみ（減算・リセットの API は無い）＝**単調増加**。

---

## C-1. トップページはカウンターを描画する

`GET /` は以下をすべて満たす HTML を 2xx で返す。

- カウント値を差し替える対象の要素 `id="count"` を含む。
- HTMX 属性（`hx-post`）を含む ＝ ボタンがサーバに POST する配線がある。
- **view-data コメントを含む。**

**境界値**: カウント値が **0** のとき、埋め込み JSON は `{"value":0}` ではなく **`{}`** になる
（proto3 JSON は 0 値を省略する ── `crates/schema/tests/unit_json_contract.rs` で固定）。
したがって **`value` というキー名の存在を条件にしてはいけない**。判定は
`<!-- view-data` というコメントの存在で行う。

## C-2. HTMX の増加は「フラグメント + 単調増加」で返る

`POST /increment`（HTMX が付ける `HX-Request: true` 付き）は 2xx を返し、応答は以下を満たす。

- **フルページではない**: `<html` と `<!doctype` のいずれも含まない。
- **先頭に view-data コメントが付く**（フルページは `</body>` 直前、フラグメントは先頭 ──
  位置の契約は `crates/webcore/tests/unit_render_view.rs` で固定）。
- view-data コメントを除いた可視部分が、**カウント値そのもの**（整数としてパースできる）。
  テンプレート `counter/count.html` が `{{ view.value }}` 一つであることに対応する。

連続して 2 回叩くと、2 回目の値は 1 回目より**大きい**（前提条件のとおり厳密な +1 は要求しない）。

## C-3. Connect API と HTML は同じカウント値を共有する

`POST /counter.v1.CounterService/GetCount` と `POST /counter.v1.CounterService/Increment`
（ともに JSON ボディ `{}`）について:

- `Increment` の返す値は、直前の `GetCount` が返した値より**大きい** ＝ 値が DB に永続化されており、
  API 経路と HTML 経路が同じサービス層・同じ 1 行を共有している。

**境界値**: ここでも 0 値は省略されるため、レスポンス JSON に `value` キーが**無い場合は 0 とみなす**。

## この仕様が守っている設計判断

- **サーバは同梱せず「待機」する**: テストはアプリをリンクせず、起動済みサーバを HTTP で叩く。
  アプリを変更してもこのクレートは再ビルドされない（`tests-http` は独立ワークスペース）。
- **HTMX はブラウザ無しで検証できる**: HTMX エンドポイントは「HTML 断片を返すただの POST」なので、
  断片の不変条件を assert すれば API レベルで足りる。ブラウザ操作そのものの検証は `browser/`（Playwright）が担当。
